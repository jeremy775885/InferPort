# InferPort 后续计划

更新日期：2026-09-26。发布基线：`v0.1.0` / `3cc9077`。
首版实现、CI、打包、PyPI 发布与干净环境安装已完成，协议库可进入按接入反馈维护的阶段。
已完成事项和限制见 [验证概览](validation.md)，本文件只维护剩余工作的优先级。

## 下一阶段：真实模型与执行端接入

按 [真实推理验证计划](integration-validation.md) 选择一个模型和执行端，依次完成：

1. 固定观测下的原生模型、本地适配器、远程推理对照。
2. 跨机器通信、状态重置、异常恢复与持续运行验证。
3. 选定仿真或真机环境的闭环验证。

首个模型、权重、数据与执行环境尚未选定。适配器留在各自业务仓库，
以两端独立安装、适配代码量、数值一致性和实际运行结果检查接口是否满足需要。
阶段步骤和验收标准统一维护在接入计划中。

## 后续维护优先级

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| 高 | 协议兼容性保障 | 保存独立于当前编码器生成的有效/非法 v1 消息样本；明确 SDK API 与线协议的变更规则；后续版本与 0.1.0 做客户端/服务端双向互通测试 |
| 中 | 持续运行证据 | 按真实载荷记录运行时间、调用数、资源趋势、延迟及断网/服务重启后的恢复结果；具体场景沿用接入计划 |
| 中 | 接入文档与故障排查 | 将首次接入整理成可复现教程，覆盖连接失败、busy、首次加载超时、消息超限及实际部署遇到的问题 |
| 中 | 开发维护规范 | 公共 API 纳入一种类型检查工具；补充简短贡献指南，说明开发命令、测试边界、版本支持与弃用方式 |

现有跨环境测试仅证明同一 SDK 在不同 Python/NumPy 环境间互通；短期资源检查不能代替长时间运行。
性能优化先区分通信、序列化和模型执行成本，实际问题与需求决定后续改动。

## 暂缓事项

保持一模型、一活动连接、数组自身承载 batch 的范围。
RTC、动作调度、自动批处理、多客户端/多模型、更多传输后端、通用 schema 和服务描述框架，
等待实际接入提出明确需求后再评估。
Python >=3.10、NumPy >=1.21.3,<3 的兼容方向保持不变，具体约定见 [协议与接口参考](inferport-design.md)。

## 维护方式

恢复工作时先核对当前代码、CI 和验证概览，再选择具体工作范围。
完成一项后更新此处对应缺口，把环境、命令与结果补入验证记录；保留失败及未运行项目。
API 或协议发生变化时更新接口参考，发布新版本时更新 [CHANGELOG](../CHANGELOG.md)，
并执行 [发布指南](releasing.md)。历史实验细节保存在 `docs/archive/`，后续结果另行记录。
